# ADR 0009: A language model for tasks of seconds, local by default, that never acts

Status: proposed (2026-10-10). Scope: `eicvibe.ai` (the models and their configuration), `eicvibe.api.assist` (what a model is told, a few tasks at a time), the viewer's Ask and the Check tab's Explain, and the administration page's AI section. Chosen on 2026-10-10: AI is an additional feature, not the center of EICViBE; a local model first, and by default; only tasks that finish in seconds; administrators may choose OpenAI or Anthropic instead.

## Decisions

1. **On by default, with a local model, and nothing depends on it.** With no options the features ask the Ollama server at `http://127.0.0.1:11434` for the first model it has; `--ai MODEL` and `--ai-url URL` choose another, `--no-ai` turns them off (`EICVIBE_AI_MODEL`, `EICVIBE_AI_URL`, `EICVIBE_AI_OFF` for server processes). `/api/v1/ai` says whether they are on, which model answers, where it runs, and whether it answers. The viewer's ✦ Ask and ✦ Explain are there whenever the features are on; when no model answers they say why and do nothing, and when an administrator turns them off they are gone. Every page works the same without them.
2. **Local first; a provider if an administrator chooses one.** The default model runs on this machine or a server of the lab's, and nothing goes anywhere else. On the administration page (AI, administrators only) the choice is a local model (Ollama, the default), OpenAI (its Chat Completions API, or a server with the same API at another URL) or Anthropic Claude (its Messages API), with a URL, a model (Test lists what the provider offers) and an API key. A key is sent once, kept in the state folder (`ai.json`, readable by its owner only, one key per provider) or taken from the server's `OPENAI_API_KEY` or `ANTHROPIC_API_KEY`, and never sent back: the page shows its last four characters. Test tries a choice before saving it and says how long a word took. Every change is an action in the log, with its reason and whether the key changed, never the key. The page says that with a provider the questions and the facts gathered for them go to the provider, and that a ChatGPT or Claude subscription does not let other applications use its models: they need an API key from the provider's developer platform. Answers say which model wrote them and where: "on this server", or "by OpenAI", "by Anthropic". On an M3 Max with 128 GB, Qwen3.8 27B (MLX, 4-bit) reads a prompt at about 190 tokens a second and writes about 20, and a prompt prefix it has read before costs nothing; the instructions come first in every prompt for that reason.
3. **Only tasks that finish in seconds.** Each feature is one model call: thinking off, the answer capped (220 tokens for Explain, 180 for Ask; more for providers' reasoning models, whose cap includes their reasoning) and stopped after 60 s, streamed as it is written. A local model answers one request at a time, a provider four; one more is told the model is busy rather than queued. Reasoning ("thinking") mode is not used: on the same machine it spent 6000 tokens (8 minutes) on one question without reaching an answer.
4. **EICViBE decides; the model puts it into words.** The facts the model sees are computed by EICViBE and gathered by the server from its own data, never sent by the browser: for Ask, the branch shown, the selected element's parameters and devices, optics only if already computed (a question never starts a computation), the machine and run chosen; for Explain, the run's check (ADR 0007). The comparisons that matter are made in code: whether the measured tune is within 0.001 of the model's, whether it equals the model's tune at the measured amplitude (amplitude detuning), the kick in beam sizes, and the kick of three beam sizes that would measure the linear tune. The next steps are a fixed list of things EICViBE offers, of which the model recommends one. The instructions forbid new numbers, judgements without a criterion in the facts, and claims of having changed anything. The reason: asked to work things out itself, the 27B model put a 1 mrad kick's amplitude at 5.7 mm instead of 32 mm, chose a 1.8 mrad "small" kick, blamed BPM gains for a detuned phase advance, suggested a tool EICViBE does not have, and called a chromaticity of +1 "not corrected"; given the facts and the verdict, it explained the same check correctly.
5. **It reads; it never acts** (for accelerator operations, ADR 0010 changes this: a model may choose vetted operations, which a person approves on shared machines). The model has no tools and no credentials, and is not on the virtual accelerator's write path (ADR 0008). Its answers are labelled with the model's name and "may be wrong", beside the numbers they explain. Reasoning text some models write even with thinking off (`<think>…</think>`) is left out of the answer.

## The features

- **Ask** (top bar): a question about what the viewer shows, answered in a few sentences.
- **Explain** (the Check tab and `check.html`): the check's reading in plain words, and one next step.

## Validation (2026-10-10)

- With no AI options the demo server found `qwen3.8:27b-mlx` itself; the administration page's Test had a word from it in 1.3 s.
- In Chrome on the demo with `qwen3.8:27b-mlx`: Ask's first words after 1.8 s, done after 4.6 s; Explain 3.3 s and 7.1 s. On the EIN's RCS run kicked by 1 mrad (192 BPMs, with tune against amplitude): Explain in 12 s, saying the tracking agrees with the model, the difference from the linear tune is amplitude detuning (57 beam sizes), and a 0.053 mrad kick would measure the linear tune.
- Tests against a stand-in server for all three APIs: status, streaming, keys (OpenAI's bearer token, Anthropic's `x-api-key` and its separate system prompt), refused keys, unknown models, a busy model, the features off; the configuration's defaults and keys; the administrators' routes (only administrators, a key kept unseen and logged as changed, each provider's key kept, a saved choice taking effect at once). Browser tests: on by default with no model answering (the buttons say so), the answers' labels with the endpoints stood in, and an administrator choosing Claude with a key that never comes back, offline.

## Not yet

- Answers of fixed shape (JSON schema) that the viewer acts on with its own code, such as choosing a tab or filtering the element table.
- Summaries of the write log and of a run's events.
- An agent with tools (writes to a sandbox, behind approval), only after a benchmark of tasks with known answers on the virtual accelerator shows a model is right often enough. Bayesian optimisation and orbit correction come before it, as tools in their own right.
- Decision models served only by outside APIs (Jev, for example): not by default; like OpenAI and Anthropic, only by an administrator's choice.
